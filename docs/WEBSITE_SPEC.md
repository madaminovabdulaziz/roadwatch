# RoadWatch — Website & Live Demo Spec

Website = 25% of elimination score. Rubric: Live demo 30%, Sample-video visualizations 20%, EDA 15%, Approach & report 15%, Team 10%, Design/UX/extras 10%.
Rule #1: **the demo must never crash on the judges' upload.** Rule #2: it must stay online through judging.

## Stack
- **Frontend:** Next.js (static export) + Tailwind + Plotly.js (interactive charts). Host on Vercel. Mobile-first.
- **Demo backend:** FastAPI in a Docker Hugging Face Space (CPU). Imports the same `roadwatch` package as the submission (copied or installed from the repo). CPU config: YOLO11s, stride 5, imgsz 640.
- **Data for static pages:** generated by scripts into `web/public/data/` (JSON + MP4 + PNG). No hand-made numbers.

## Pages / sections
1. **Home:** one-line pitch, 20 s hero clip of an annotated sample, three key numbers (classes covered, dev F1, runtime × duration), buttons: Try the demo / Read the approach.
2. **Team:** 3 cards: photo, name, role, what they built (concrete), GitHub, LinkedIn, portfolio, 1–2 past projects each.
3. **Approach:** pipeline diagram (SVG/Mermaid): decode → detect → track → metres → scene rules → post-process → events; Part B branch. Table: what is learned (detector) vs rule-based (everything else) and why. Models + datasets + licences. Scene calibration screenshot with all layers drawn.
4. **EDA:** resolution/fps/duration/lighting table per sample; object counts over time by class (Plotly stacked area); motion heatmap overlay; trajectory plot coloured by direction; learned lane-direction field (arrows) → "this is how we got wrong_way"; density per minute; speed distribution per lane; light-phase timeline. Each chart has a one-sentence "what this changed in our solution".
5. **Results:** per sample video: annotated playback + clickable event timeline (click → seek), risk curve under the video synced to playback, events table. Per-class gallery (one clip per detected class). Dev-set per-class F1 table + confusion view. **Honest failure cases** with short clips and why.
6. **Live demo:** upload .mp4 (≤ 2 min, ≤ 100 MB, stated clearly) → progress bar → annotated playback + timeline + risk curve + events table + download JSON. Two built-in example buttons (preloaded sample clip) so judges can see output even without their own file.
7. **Dashboard (extra credit):** operator view: events per class, per lane, per minute, heat of event locations on the reference frame.
8. **Report:** one page: what we built, what worked, what did not, what we'd do next.
9. **Links:** repo, weights archive, `predictions_samples.json`, README.

## Demo API (backend contract)
```
POST /api/jobs            multipart file=video.mp4 -> {"job_id": "..."}
GET  /api/jobs/{id}       -> {"status": "queued|running|done|error", "progress": 0-100,
                              "stage": "decoding|detecting|rules|rendering",
                              "result": {"events": [[s,e,label],...], "risk": [[t,score],...],
                                         "video_url": "/api/files/{id}/annotated.mp4",
                                         "camera_match": true, "duration": 118.2}}
GET  /api/files/{id}/annotated.mp4
GET  /api/health
```
- One worker, in-memory job queue, jobs expire after 1 h, files deleted after 1 h.
- Validate: extension, size, duration ≤ 120 s (reject with a friendly message, never 500). Re-encode odd inputs with ffmpeg first.
- **Annotated MP4 must be H.264 (`libx264`, `yuv420p`, `+faststart`) via ffmpeg**, otherwise browsers won't play it.
- **Camera match:** compare the upload's median frame to `configs/reference.jpg` (resize + ORB match count or SSIM). If no match: run only camera-independent classes (accident, near_miss, stopped_vehicle without queue logic, jaywalking on detected road area disabled → skip, congestion by global speed), show a banner "Different camera: scene-specific rules disabled".
- Any internal error → status `error` with a readable message; frontend shows retry. Never hang.
- Keep-alive: an external uptime ping every 10 min on `/api/health`.

## Visual rules for annotated video (`roadwatch/render.py`)
- Boxes coloured by class; track id + speed (km/h) small label; footprints trail (last 2 s).
- Scene layers drawn semi-transparent (lanes, stop lines, crosswalks).
- Active events as banners top-left with class colour; risk bar top-right (green → red, 0.5 line).
- Traffic light state indicator.
- Optional: blur faces (person box top 20%) and plates for privacy.

## Design
Dark, clean, one accent colour per event class (same colours in video, timeline, charts). Fast: videos lazy-loaded, posters for each clip. Test on a phone before submitting.
